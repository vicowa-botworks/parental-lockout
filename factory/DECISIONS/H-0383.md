- Question: #488 is phase 3 of the layout split (#429, H-0263): every entry leaves the two monoliths
  and becomes one file beside them. Phase 1 (#442) taught the gate to read both layouts, phase 2
  (#456) taught the allocator to emit filed ids, and the ticket says the move itself goes in batches
  of about forty with `make verify` between them. Measured at `42dea11` on this branch: 5,651 lines
  and 78 `D-` entries in the product log, 19,253 lines and 359 `H-` entries in the harness log, 437
  to move, 11 entries already filed by phase 2 across both directories. The cost that decides how is
  not the moving, it is the pointers: the gate refuses a `path:line` whose quoted anchor is not on the
  row it names, so deleting an entry from the middle of a log mis-aims every coordinate under the cut
  -- including the ones aimed at entries that stayed, because their rows moved too. One pass reads
  1,402 coordinates out of these logs, 1,200 of them anchored, and 41 of the checkable ones carry no
  anchor at all, which is the class nothing can judge after the fact.
- Options: hand-file each batch in an editor | file the batch and leave every coordinate as written |
  file the batch and re-aim the coordinates from one row map, as a committed tool | one commit for all
  437 entries
- Chose: file the batch and re-aim the coordinates from one row map, as a committed tool
- Why: `scripts/split-decisions.py` files one batch -- the oldest entries through `--through <id>`,
  the preamble plus the survivors rewritten in place -- and re-aims every citation in the whole union
  that points into the log whose rows it moved, in the same commit as the move. The map is three lines
  of arithmetic: a row inside a moved entry becomes that entry's own file at `row - heading + 1`; a
  row that stays keeps the monolith and loses the lines removed above it; the preamble sits above
  every cut so its rows never move. Continuations are rewritten too, and a bare `:12339` has its path
  written out, because after the split its target may live in a different file while the sentence
  around it still names the monolith. Revision-qualified coordinates (`3c09d6b:factory/DECISIONS.md`
  at line 7545) are left alone: they state the tree to open, so they cannot drift. A range whose two
  ends land in two files is refused (`range-split`) rather than guessed, and so is a batch whose rows
  do not partition the file, and so is filing an entry whose file already exists (`already-filed`),
  which is the duplicate #442 counts. Why the map is trustworthy for the 41 pointers nothing judges:
  the rewrite never touches an anchor's bytes, so every anchored pointer re-verifies against the row
  its new coordinate names, the map is one function over rows rather than one judgement per citation,
  and wrong arithmetic is therefore a red gate on the ~1,200 checkable pointers, not a quiet drift on
  the 41 uncheckable ones. `merge-decisions.py` already trusts that argument for a two-sided merge
  (#381); this applies it to a one-sided move. The other three lost as follows. Leaving the
  coordinates was rejected because #456 already priced a pointer that lies above a pointer that is
  missing, and `POINTER_DEBT` cannot see a silent one: the ratchet would hold its number while its
  meaning changed. A hand pass was rejected on this project's own record (#1180, #2694: confident
  receipts for commands that were never run) -- 437 entries is the longest unattended hand pass this
  loop has ever been asked to make, and the pointer work inside it is the part with no anchor to
  check it against. One commit for all 437 was rejected on the conflict-wave budget #456 measured,
  not on taste: 18,000 lines with no bisectable batch lands on every open branch at once. Batch from
  the newest end, the other order available, was rejected because it still moves every coordinate
  aimed below the cut and it files the newest entries first, which is exactly where a half-finished
  split would collide with a sibling's new entry. What the batch is measured to cost, dry run at
  `42dea11`: `--through H-0040` files 38 entries, 19,253 lines to 18,369, and re-aims 48 citations in
  `factory/DECISIONS.md` with no refusal and no coordinate past the end.
- Confidence: high for the mechanism, medium for this branch's coverage of it. The mechanism carries a
  20-assertion `--self-test` in the script: a pointer into a moved entry arriving from the preamble,
  from a moved sibling, from a staying entry and from the other log; a bare continuation whose file
  changes underneath it; a range across two rows of one moved entry; a pinned coordinate that must NOT
  move; a pointer to the preamble, which is above every cut; and both refusals, `already-filed` and
  `range-split`. Its fixture coordinates are counted from the rows its anchors are actually on, because
  a hand-counted fixture row is the same mistake the script exists to prevent -- the first draft of it
  aimed three assertions at row 3, which was the preamble's quotation of the anchor, and the failure was
  in the fixture, not the tool. What is medium is coverage: this branch ships the tool, the recipe and
  the hand-off, and the number of batches actually run before the pull request opened is ZERO, because
  the 45-minute ceiling arrived first; every number quoted above is a dry run, which writes nothing.
