## D-0094 · PR #521 conflicts with the shipped navigation design: take `main`’s implementation and preserve the drop record

- Question: #521 was opened from `wip/issue-204-dropped-6bfd528` to preserve the dropped
  `.Page` record. `origin/main` has since shipped path-based navigation: `sources.go`
  derives `IsCurrent` from the request path, `page.tmpl` renders that result, and
  `nav_test.go`'s `TestTheCurrentEntryIsTheSectionThePathIsIn` table records the rule the
  shipped design has to keep. The branch instead extends the `.Page` record `D-0053` dropped
  and its tests. Should the conflict be resolved by reviving the dropped
  implementation, taking `main` wholesale and losing the branch record, or taking `main`
  for the implementation while preserving the branch’s decision record separately?
- Options: take the branch’s implementation and reverse the shipped `D-0033` comparison | take
  `main` for every path and discard the branch record | take `main` for the three web
  paths, keep `main`’s `DECISIONS.md` intact, and file the branch-only `D-0053` record |
  keep both implementations behind a selector
- Chose: take `main` for the three web paths, keep `main`’s `DECISIONS.md` intact, and file
  the branch-only `D-0053` record
- Why: the branch’s implementation is the second option `D-0033` weighed — "the page's own
  `pagename` definition, compared against each href in the shell" — which that entry priced and
  chose against, and which no `main` lineage ever carried; while
  `main` has spent the eighteen days since `13e02ef` building guards around the path-based rule
  it chose. Reviving it
  would make a preservation pull request reopen a reviewed product decision; a selector
  would preserve a second marking rule without earning it. #204 asks for the work, not the
  shipped behavior, and `D-0053` is the work: it records the independent design and the
  page-marking contradiction that prevented an unexamined merge. `D-0053` is filed outside
  the monolith so `main`’s published log rows and citations keep their seats. This entry
  resolves the product conflict only. The branch also carried a branch-local `D-0015` that
  collides with the published `D-0015`; it is deliberately not smuggled into this commit
  under an unallocated id, and the allocator will issue its replacement id in the follow-on
  record decision.
  Where the two ids this entry first carried came from, measured 2026-11-23 on #521's review
  round and disclosed here instead of left as a mis-citation: the comparison entry was authored as
  `D-0025`. `git show 13e02ef:DECISIONS.md` carries it under that number with the heading
  "The shell is told the path, and one segment decides which entry is current", and

  capture entry `787a1f2` claimed two and a half hours later on the same date, and the number
