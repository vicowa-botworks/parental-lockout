## D-0102 · #526 review: the install guarantee moves from a goal ordering to a prerequisite edge (`install-verified`)

- Refs #525 -- the ticket D-0100 delivered; #526's review of that head found the shipped
  guarantee did not hold, and this entry repairs it. The closing keyword stays where
  D-0100's pull request put it.
- Question: PR #526's review (24 Nov, `CHANGES_REQUESTED`) measured that `make verify
  install` -- the ordered-goal form D-0100 shipped as "the shipped shape of the guarantee"
  -- is ordered only for a serial make of two goals: with `-j`, `-k`, or `MAKEFLAGS`
  carrying a job count, the command-line goals are independent and the installer runs while
  the gate is failing. This tick reproduced it on the head's own target shape (GNU Make
  4.4.1): `-j8`, `-k` and `MAKEFLAGS=-j4` ran a probe installer with the gate refusing,
  `-j2` installed on 1 of 5 runs (a race, not a clean row), and only serial held; on a
  clone of the real Makefile at head with `deploy/install.sh` replaced by a probe,
  `make -j8 verify install` printed the probe while the gate was still at
  `==> factory dirt verdict`, where the serial control never reached the installer. An
  operator who exports `MAKEFLAGS` hits this without typing `-j`. That is the product's own
  silent failure -- a root daemon enforcing from a binary the gate rejects -- while the
  docs assert the opposite in five places. Which repair keeps D-0100's win, a gate-free
  everyday `make install`?
- Options: a named umbrella target `install-verified` whose `verify` prerequisite orders the gate and whose recipe runs the install recursively | document the two commands `make verify && make install` and change no Makefile | put `verify` back on `install` as an order-only prerequisite (`install: build | verify`)
- Chose: a named umbrella target `install-verified` whose `verify` prerequisite orders the gate and whose recipe runs the install recursively
- Why: tie-break 1 and 2 decide nothing (no dependency, no config decode). Tie-break 3
  (refuse rather than proceed) picks the prerequisite edge, measured both ways on the
  fixture at the head's target shape: with a red gate `install-verified` never ran the
  installer under `""`, `-j2`, `-j8`, `-k`, `-j4 -k` or `MAKEFLAGS=-j8` (rc 2 each time),
  and with a green gate it installed exactly once (rc 0). The doc-only arm keeps printing a
  one-command form that is false the moment `MAKEFLAGS` carries a job count -- the operator
  reaches the silent failure without typing `-j`, which is the complaint that opened #525
  wearing a new face. The order-only arm was measured, not waved at: a bare
  `make install-orderonly` fixture target ran the gate before the probe, so it restores the
  minutes-long battery to the everyday path -- the exact shape #525 was filed against.
  Tie-break 5 holds: one `git revert` of the commit carrying this entry's trailer returns
  to D-0100's head. What lost, stated as lost: the sentence operators were taught changes
  name -- muscle-memory `make verify install` still parses, still installs gate-free under
  `-j`, and is no longer printed anywhere as the guarantee; the umbrella is a recursive
  make, so the gated path pays one extra make invocation; and D-0100's `Chose:` still names
  the ordered-goal form, which the dated Correction appended under its `Checkpoint:` now
  points at this entry rather than the entry being rewritten (rewriting it would falsify
  what `13137be` decided).
- Effect: the Makefile gains `install-verified` (a `verify` prerequisite, a recipe of
  `$(MAKE) --no-print-directory install` so it can never drift from what plain install
  does) and its `.PHONY` entry; the comment over `install` now states the measurement
  against goal ordering instead of claiming it; `README.md` and `docs/setup.md` print
  `sudo make install-verified`; the cross-reference in the comment over `run-dev`, which
  still claimed `verify` was install's prerequisite, now names `install-verified`; the
  five places that asserted the goal-order mechanism assert the prerequisite edge or are
  corrected (D-0100 carries the dated Correction; `NEXT.md` re-heads). Both fixture legs
  and the real-Makefile probe run are recorded on the pull request beside this commit.
